## Data Flow Examples

### How a Real Packet is Processed

```
1. Network Interface
   ↓
2. Scapy: sniff() captures raw packets
   ↓
3. Packet Parser: Extracts IP/TCP/UDP/ICMP layers
   ↓
4. Feature Extractor: Converts to 78 features
   ↓
5. Hybrid Detector:
   - ML Model (confidence >= 0.7) → Prediction
   - Rule Engine (confidence < 0.7) → Fallback rules
   ↓
6. Results Stored:
   - packets table (all traffic)
   - detection_events table (attacks only)
   - NIDS_STATE.recent_packets (RAM)
   ↓
7. API Endpoint:
   GET /api/packets → Returns real captured packets
   ↓
8. Frontend:
   Live Monitor displays real packets in table
```

### How Real Analytics are Generated

```
1. Real Detection Events (from database)
   ↓
2. SQL Query: SELECT attack_type, COUNT(*) FROM detection_events GROUP BY attack_type
   ↓
3. Results: [
     { name: 'Port Scan', value: 45, color: '#ff006e' },
     { name: 'DoS', value: 28, color: '#b536d9' }
   ]
   ↓
4. API Endpoint: GET /api/analytics/attack-distribution
   ↓
5. Frontend: Recharts PieChart renders real distribution
```

## Troubleshooting

### Problem: "Failed to fetch /api/stats"
**Solution**: Make sure backend is running on port 8081
```bash
cd backend
python app.py
```

### Problem: Packet capture not working
**Solution**: May need elevated privileges
- **Windows**: Run cmd as Administrator
- **Linux**: Use `sudo` or add user to network group
- **Fallback**: System will use mock packets if Scapy fails

### Problem: No data showing
**Solution**: Wait 10-30 seconds for packets to be captured
- Initially, database is empty
- Packets and detections accumulate over time
- Check database: `sqlite3 nids.db "SELECT COUNT(*) FROM packets;"`

### Problem: Too much data (slow performance)
**Solution**: Limit packet buffer
- Edit `backend/app.py` line: `app.config['MAX_PACKETS_MEMORY'] = 10000`
- Reduce to 5000 or 2000 if needed
